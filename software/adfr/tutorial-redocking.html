Tutorial: re-docking a ligand

This tutorial re-docks a known ligand into its native receptor: one of the ligands of cyclin-dependent kinase 2, CDK2 (PDB 4EK4), into the CDK2 structure PDB 4EK3.

You will learn to:

  • generate a target file for docking in a box defined by the known ligand
  • run ADFR to re-dock the ligand
  • understand the output of an ADFR docking run

Prerequisites: ADFRsuite 1.0 installed with ADFRsuite-1.0/bin on your PATH, and the tutorial data downloaded and unzipped (see Tutorials). Run the commands from the folder that contains data/.

1. Generate the target file

agfr -r data/4EK3_rec.pdbqt -l data/4EK4_lig.pdbqt -o ligPocket

You can also use agfrgui and follow the AGFR box around a ligand tutorial.

Option Meaning
-r the receptor file (required)
-l the ligand file
-o name for the target file

Details. agfr positions and sizes the docking box over the receptor pocket(s) where the ligand will be docked, and computes affinity maps for a list of AutoDock4 atom types. The maps are calculated by AutoGrid4.

  • Box. The box can be set in several ways with -b/--boxMode. Here agfr uses the bounding box of the known ligand (-l/--ligand), with 4 Å of padding added on every side. Change the padding with -P/--padding.
  • Output. The target file (.trg) is saved under the name given by -o/--output; without it, a unique descriptive name is created. It contains the affinity maps, translational points for placing the ligand at sensible positions in the box, and metadata about the grid size, position and spacing, the receptor atoms involved and the maps. Inspect it with the about command.
  • Pockets. The translational points are computed by AutoSite, which clusters high-affinity grid points into potential binding pockets. -p/--pocketMode sets how multiple clusters are handled; when it is omitted, as here, all clusters are merged into one set of translational points.
  • Atom types. By default maps are computed for all AutoDock4 atom types. Restrict them with -m/--mapTypes for smaller files and faster runs, but the target file then cannot dock ligands with atom types it has no map for.

3. Dock the randomized ligand

adfr -l data/4EK4_random.pdbqt -t ligPocket.trg --jobName rigid --nbRuns 8 --maxEvals 20000 -O --seed 1

adfr detects the available cores and uses all of them by default. Here it runs 8 independent searches (--nbRuns 8), each with up to 20,000 evaluations of the scoring function (--maxEvals 20000). By default adfr runs 50 searches of 2.5 million evaluations each. Harder docking problems need more searches to raise the chance of finding the best pose (the global minimum of the scoring function). The low values here give a quick run that is enough to show how docking works.

The run writes:

File Content
4EK4_random_rigid_summary.dlg the docking log, with most of what is shown on the terminal
4EK4_random_rigid_out.pdbqt the docked poses
4EK4_random_rigid.dro the docking result object: input, output and metadata of this run
TipNotes
  • Output files are named after the ligand, followed by the job name (--jobName, if given).
  • The search is stochastic: docking the same ligand into the same target twice can give different results with different random seeds. The energy landscape is the same in both runs; if both find its global minimum they give the same solution, whatever path the search took. Searches trapped in local minima give different poses. Setting the seed (--seed) makes a run reproducible for a given version of the code.

By default ADFR runs 50 independent searches, that is 50 evolutions of a population of 100 individuals with a genetic algorithm (GA). Here we deliberately reduced this to 8 very short runs. Lines 1–4 are a progress bar showing the percentage of runs completed.

The lines below give statistics on how the searches ended. ADFR has several termination criteria. In this example every search stopped because it used up its evaluations. The default of 2.5 million evaluations is usually never reached, because other criteria stop the search first: the population converges (no diversity left, so new solutions are unlikely), or the population still holds several competitive solutions but none has improved for a set number of generations (default 5).

You want searches to end because the population converged or stopped improving. A result like this one clearly shows that the problem needs more evaluations per search (a larger --maxEvals).

done.

Here the 8 searches found 3 distinct solutions, sorted by predicted affinity, best first. The top solution was found by 4 of the 8 searches (clust. size), and its best pose came from search 4 (best run). The second solution was found 3 times; its best pose is 5.0 Å RMSD from the top solution (clust. rmsd). With a reference ligand (-r/--reference), the ref. rmsd column would give the RMSD of each pose to the reference instead of −1.

Note

RMSD values are computed over all isomorphisms between the two molecules, matching symmetry-related atoms. This is more accurate than the RMSD in AutoDock4, Vina and earlier versions of AutoDockFR.

Exercise: re-dock the ligand reliably

The command

adfr -l data/4EK4_random.pdbqt -t ligPocket.trg --jobName rigid --nbRuns 8 --maxEvals 20000 -O --seed 1

gives 3 distinct solutions. Can you change it to re-dock the randomized ligand into its crystallographic pose reliably? The crystal structure of the ligand is in data/4EK4_lig.pdbqt.

TipAnswer

With the command above, every search ended while it was still improving its solutions. The natural first step is therefore to give each search more evaluations so it can converge. The default of 2.5 million is a good choice: unlike AutoDock4, ADFR only keeps searching while improvements are seen or can be hoped for.

Giving the crystal structure as a reference (--reference) also reports the RMSD between each docked pose and the crystal structure.

Finally, the job is named rigid1, so adfr does not stop because output files with the same name already exist. (-O overwrites existing files silently.)

adfr -l data/4EK4_random.pdbqt -t ligPocket.trg --reference data/4EK4_lig.pdbqt --jobName rigid1 --nbRuns 8 -O --seed 1

The run takes longer, but all searches now converge:
