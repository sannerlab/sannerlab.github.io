Tutorial: docking a covalently bound ligand

This tutorial re-docks the native covalent ligand of PDB 3C9W. The receptor (3c9w.pdbqt) and the ligand (3c9w_ligandWithSideChain_random.pdbqt) are in the tutorial data.

For covalent docking, the receptor and the covalent ligand must share 3 atoms, as shown below: 2 atoms (green) form the covalent bond, and 1 atom (yellow) is an anchor on the receptor side. These atoms are used to move the ligand into place relative to the receptor and create the covalent bond.

Note

Covalent docking needs no translational points: the covalent bond positions the ligand in the docking box.

You will learn to:

  • generate a target file for covalent docking
  • run ADFR to dock the ligand
  • understand the output of an ADFR docking run

1. Generate the target file

agfr -r data/3c9w.pdbqt -b user 28.565 6.329 6.985 22.5 22.5 22.5 -c 1593 1596 -t 1591 -x A:CYS164 -o 3c9w_cov_cmdline

Details:

  • The box position and size are set by hand here to show this option. This is the only -b/--boxMode option that ignores padding.
  • -c/--covalentBond gives the serial numbers of the 2 receptor atoms that form the covalent bond, as they appear in the PDBQT file.
  • -t/--covalentBondTorsionAtom gives the third atom of the covalent attachment, used to compute the torsion angle of the covalent bond.
  • -x/--covalentResidues limits the traversal of the receptor to a list of residues. This is sometimes needed because covalent ligands can form bonds with the receptor other than the covalent attachment, as the native ligand of 3C9W does. When agfr walks the sub-tree beyond the covalent bond to find which atoms to cut out of the receptor for the affinity maps, that spurious bond would make it include a large part of the receptor, cutting out more than 1600 atoms. -x prevents this.
  • The target file is called 3c9w_cov_cmdline.trg (-o).

3. Dock the randomized ligand

adfr -l data/3c9w_ligandWithSideChain_random.pdbqt -t 3c9w_cov_cmdline.trg --jobName covalent -C 1 2 3 --nbRuns 8 --maxEvals 100000 -O --seed 1

This re-docks the native ligand after randomizing it (its conformation, position and orientation in the crystal structure were changed at random). -C 1 2 3 names the 3 ligand atoms that match the covalent attachment atoms of the receptor (see the figure above). adfr detects the available cores and uses all of them by default. Here it runs 8 independent searches (--nbRuns 8), each with up to 100,000 evaluations of the scoring function (--maxEvals 100000). By default adfr runs 50 searches of 2.5 million evaluations each. The low values here give a quick run that is enough to show how docking works.

The run writes:

File Content
3c9w_ligandWithSideChain_random_covalent_summary.dlg the docking log, with most of what is shown on the terminal
3c9w_ligandWithSideChain_random_covalent_out.pdbqt the docked poses
3c9w_ligandWithSideChain_random_covalent.dro the docking result object: input, output and metadata of this run
TipNotes
  • Output files are named after the ligand, followed by the job name (--jobName, if given).
  • The search is stochastic; setting the seed (--seed) makes a run reproducible for a given version of the code. See the re-docking tutorial.
