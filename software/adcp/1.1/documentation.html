ADCP 1.1 documentation

Note

The CCSB page for this version says it is under construction. For now it gives a few example runs that show the new capabilities of version 1.1.

To run these examples, download the receptor and the ligand for PDB 3Q47.

Create a target file

This command computes the target file 3Q47.trg:

agfr -r 3Q47_recH.pdbqt -l 3Q47_pepH.pdbqt -asv 1.1 -o 3Q47

agfr runs AutoGridFR, which computes target files.

Option Meaning
-r the receptor, here as a PDBQT file
-l the ligand, here the crystallographic peptide. When a ligand is given, agfr defines the docking box as the ligand’s bounding box with 4 Å padding.
-asv 1.1 compute the preferred starting ligand positions in the box with AutoSite 1.1, rather than 1.0, which is meant for small molecules
-o 3Q47 name of the target file to write (3Q47.trg)

Run ADCP with modified amino acids

adcp -T 3Q47.trg -s "n<BHD>pis&dvd" -N 2 -n 2000 -L swiss -w testDir -o testNSAAandD

In version 1.1 the peptide sequence can contain non-natural amino acids, written as [&]x<NAME>:

  • The optional & makes the amino acid D instead of the default L chirality.
  • x is the coarse bead that represents the side chain. Any one-letter code of a natural amino acid can be used here.
  • The modified side chain’s name goes between chevrons, <>.

In the example, the first amino acid is represented as an asparagine in the coarse model, and an asparagine derivative side chain (BHD) from the Swiss side-chain library is used for the full-atom representation. The peptide also contains a D-aspartic acid at position 5.

Tip

The modified side chain is loaded from a library file, here the Swiss library selected with -L swiss.

This example runs only 2 Monte Carlo searches (-N 2) of 2000 evaluations each, so that it finishes quickly; it is not meant to find real docked poses. It writes two files into the working directory testDir (-w):

  • testNSAAandD_out.pdb: a multi-model PDB file with the docked poses
  • testNSAAandD_summary.dlg: the docking log

OpenMM minimization

ADCP 1.1 can minimize docked poses with OpenMM and re-rank them. These examples assume you already know the standard ADCP options.

Re-ranking poses of standard amino acids

The option -nmin turns on OpenMM minimization of poses, followed by re-ranking. This example docks the peptide grctksicfpd into the receptor from 3Q47.trg and minimizes the top 5 docked solutions with OpenMM:

adcp -O -T 3Q47.trg -s "grctksicfpd" -cyc -N 5 -n 100000 -w testDir1 -o example1 -nmin 5

Besides the default ADCP output, this command writes:

  • example1_omm_rescored_out.pdb: the minimized and re-ranked top solutions (receptor + peptide)
  • testDir1/example1_omm_amber_parm/: Amber topology and coordinate files for each re-ranked solution, for further analysis or free-energy calculations with molecular dynamics or other molecular mechanics methods

Additional options

The number of minimization steps (-nitr), the solvent environment (-env) and the output order of re-ranked solutions (-dr) control the minimization. For example:

adcp -O -T 3Q47.trg -s "grctksicfpd" -cyc -N 5 -n 100000 -w testDir1 -o example1 -nmin 5 -nitr 500 -env implicit -dr -reint
Option Meaning
-nitr 500 500 minimization steps for each docked pose
-env implicit minimize in implicit solvent (default: vacuum)
-dr report minimized solutions ordered by docking score, best to worst (default: OpenMM ranking score)
-reint rank by interaction energy (Ecomplex − Ereceptor − Epeptide) instead of (Ecomplex − Ereceptor)

Minimizing poses that are already docked

  • Post-docking minimization (-pdmin) applies OpenMM minimization to poses that were already docked. ADCP skips docking and minimizes the poses from the earlier output file. Use the same target file (-T), job name (-o) and sequence (-s) as in the docking run.
  • Resume a failed minimization (-resumemin) continues an interrupted minimization and re-ranking. It works only together with -pdmin and without overwriting (-O).

Non-standard amino acids

The default force-field parameters for OpenMM minimization lack most non-standard amino acids. ADCP therefore uses the “sannerlab” OpenMM parameter set for 182 non-standard amino acids and the “swiss” set for 20 non-terminal ones. These sets are designed for the Swiss non-standard amino acids and need proper licensing from the developer of the SwissSideChain database. The full list of supported residues is in ADCP/data/openMMff/AVAILABLE_PARAMETER.dat.

When no OpenMM parameters exist for a non-standard amino acid, ADCP uses pdbfixer (v1.8) to replace it with a standard one. If pdbfixer cannot replace it, the residue is mutated to alanine for the OpenMM re-ranking.

Option Meaning
-F which OpenMM parameter sets to use from ADCP/data/openMMff (swiss, sannerlab or none); none turns off all system default sets
-f user-supplied OpenMM parameters for new or unlisted non-standard amino acids (see below)

-f needs three files in the same directory with the same stem. For -f ./XXXX_ff.xml the program expects a force-field file ./XXXX_ff.xml, a bond definition file ./XXXX_residues.xml and a hydrogen definition file ./XXXX_hydrogen_def.xml.

Non-canonical amino acids

ADCP 1.1 docks peptides that contain non-natural amino acids (NSAAs). Each NSAA has a name (for example PTR), and ADCP reads its side-chain parameters from library files given on the command line (-l and -L). ADCP ships with a library for the natural amino acids (always loaded) and a library of fluorinated amino acids.

We also developed parameters for all amino acids of SwissSideChain. Its license will be replaced by CC-BY 4.0, and we have been granted the right to distribute the ADCP library for this set of 209 amino acids in D and L forms.

The library covers 182 of the 209 SwissSideChain amino acids, in both L and D chirality. This lets ADCP handle every non-natural amino acid currently found in the Protein Data Bank. To use peptides with NSAAs at any position in OpenMM, we:

  1. Computed partial charges. SwissSideChain’s charges were designed for NSAAs away from the peptide termini, so we computed charges for terminal and non-terminal forms with the R.E.D. server (RESP ESP charge Derive), using GAMESS, following this tutorial. Each form was capped with ACE and/or NME.
  2. Found force-field parameters. parmchk2 from AmberTools identified the Amber parameters needed (bonds, angles, dihedrals, impropers, electrostatics, van der Waals) from the R.E.D. mol2 files, written as an frcmod file.
  3. Built FFXML files. ParmEd converted the frcmod and mol2 files into OpenMM FFXML files for each variant. These were merged into one file covering all parameters for 184 NSAAs, which OpenMM can load.

To use these parameters in OpenMM we also changed how each structure is loaded, cleaned and simulated:

  1. Kept pdbfixer from removing or swapping NSAAs, by loading the residue definition file and editing pdbfixer.nonstandardResidues.
  2. Added OXT to C-terminal NSAAs. pdbfixer adds hydrogens with Modeller and handles N-terminal residues correctly, but not terminal NSAAs.
  3. Overrode the default hydrogen definitions, to add NSAA-specific ones or apply specific parameter sets to residues with identical names (for example ORN).
  4. Gave residues with identical molecular structures (for example THR and ALO) their own residue templates.
  5. Overrode PDB writing to handle 4-letter residue codes, with a modified PDB writer.
