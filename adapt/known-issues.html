Known issues

Everything known to be surprising or missing, in one place: what it affects, where it comes from, and where it is explained.

The defects listed here before ADFR 0.0.23 (tied alternate locations, symmetry copies that kept the defaults, unsupported atoms written or silently dropped, the rotamer preview, PDB-only input, sessions lost on a restart, wrong ion charges, and the header lines that misreported a file) are corrected; ADapt and AGFRgui lists them. What remains is mostly behaviour by design. The Origin column says whether it is ADFR's, which ADapt shares because it runs ADFR's own code, or ADapt's.

What is written into the files

IssueEffectOriginDetails
A rebuilt loop is one modelA gap's residues are built once, from one seed, without knowledge of the binding site; the loop is a plausible conformation with sane geometry, not the loop's position. A missing loop near the site is still a reason to choose another copy, assembly or entry.ADaptRebuilding a gap
Some gaps cannot be rebuiltMissing termini are not offered, nor gaps whose residues REMARK 465 does not list, gaps with a modified residue other than MSE, and gaps whose loop fails the geometry checks (4A1X B: GK). The tree gives the reason.ADaptRebuilding a gap
Rebuilt residues are not in ligandsA gap is filled in the receptor only; a chain written as a ligand keeps its gap.ADaptRebuilding a gap

What the files record about themselves

IssueEffectOriginDetails
Symmetry copies get new chain identifiersIn the receptor files a copy's chain is renamed (0, 1, …), because reduce needs unique chain names and ADFR does not rename them back. This holds for the PDBQT, and for the atoms and the USER MOD lines of _rec_H.pdb. ADapt records each rename in session.json (chain_renames).ADFRBiological assembly, the protonated receptor
A ligand's atom records say chain AThe atom records of a ligand file label the chain A whatever chain the ligand came from. The coordinates are right, and the header records the true origin (REMARK 850 AGFR ligand from B:EYB:402:_).ADFRProvenance
Some choices are recorded only in the sessionWhich hetero groups and waters were kept, and ADapt's version, are not in the PDBQT header; session.json has them.ADaptProvenance

Input and tools

IssueEffectOriginDetails
A PDB file's id comes from its file nameADFR looks up an entry's known ligands by its id. For a PDB file it is taken from the file name: name files by their id (6ggd.pdb, 6ggd.pdb.gz), or ligands land in other. An mmCIF file carries its id.ADFRLigands
Copies defined only by MTRIX are not builtAssemblies come from REMARK 350 (or, in mmCIF, pdbx_struct_assembly_gen); non-crystallographic copies that a file gives only as MTRIX records are not generated.ADFRBiological assembly
The agfr launcher splits quoted optionsThe agfr / agfrgui scripts pass their arguments unquoted, so an option value containing spaces (--heteroToKeep "chid B resnum 402") is split and rejected. Use python -m ADFR.bin.runAGFR. The correction is part of the ADFR packaging, to ship with the next ADCP release.ADFR launcherWriting the files
Needs the ADCP environmentADapt runs ADFR from the ADCP distribution's Python 3.7 environment (adcpsuite), with ADFR 0.0.23 or later; it does not work without it.ADaptGetting started
