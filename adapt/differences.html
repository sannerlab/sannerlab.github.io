ADapt and AGFRgui

The same analysis and the same files, in a browser, with more choices and a record of every one.

ADapt is the PDB analyzer of AutoGridFR's graphical interface (AGFRgui) rebuilt as a web page. It does not reimplement the chemistry. The assemblies, categories, defaults, side-chain completion, mutations, protonation, charges and PDBQT writing are all ADFR's own code, run from the ADCP distribution (adfr 0.0.23 or later, with MolKit2 0.0.6; ADapt refuses to start with an older ADFR). Only the Qt interface was rewritten. For the same choices, the receptor ADapt writes is byte-identical to the one ADFR's command line writes; ADapt's test suite checks this on ADFR's own test files. Every choice ADapt offers for the receptor except rebuilding a gap (ADapt's own, below) has a command-line option, so a receptor can be rebuilt without ADapt from the choices session.json records:

Choiceagfr optionExample
Assembly--bioMol--bioMol 2
Hetero groups kept, residues removed--heteroToKeep, --protToRemove--heteroToKeep "chid B resnum 401"
Alternate location--altlocs--altlocs "A:SER:166::A"
Mutation--mutate--mutate "B:SER:96::ILE"

Corrected in ADFR 0.0.23

These were defects of ADFR 0.0.22, found while building ADapt and corrected in ADFR itself, so agfr and AGFRgui benefit too. Each correction comes with a test in ADFR's tests/ that fails on 0.0.22.

  • Default alternate location. Ties were broken by Python's set order, so the default could change from run to run (all seven altloc residues of 1FV1 tie). Now: most atoms, then highest occupancy, then the first letter. A residue joins the receptor according to its category only; a glycerol with one larger location used to be put in.
  • Ion charges. The default is the charge the Chemical Component Dictionary gives the residue name: FE +3 and FE2 +2 (an FE2 or MN3 used to stop the file from opening), MN +2 (was +4), BR −1 (was +1). Chloride and iodide ions are manual-charge ions at −1 (chloride was other, written 0.00). Bonded chlorine and bromine get their Gasteiger charge (MolKit2 0.0.6). The ions of symmetry copies keep their charge (a copy's zinc was written 0.00).
  • Unsupported atoms. A residue with an atom AutoDock 4.1 cannot type starts outside the receptor whatever its category; cofactors such as vitamin B12 used to be written with the type CO. Kept anyway, it is dropped when the file is written and named in the header. A single unsupported ion can be replaced by Zn, Mg, Ca, Fe or Mn.
  • The chosen rotamer is built. The rotamer drop-down was a preview: the best-scoring rotamer was always built.
  • Every receptor choice has a command-line option: --altlocs, --rotamers, --sidechainsAsIs and --substitute are new.
  • Missing residues are detected. The test for a gap in the alignment was always false; it is corrected, along with the defects that test had been hiding (see Missing residues). The PDBQT files do not change.
  • Assemblies. From ten assemblies on, a tab could hold another assembly's atoms; an assembly is now built by its number, and tabs are in numerical order. An assembly shares the ASU's tab only when it is the ASU's chains without transformation.
  • Input. mmCIF files are read, and a gzipped PDB file keeps its header (assemblies, sequences and missing residues were lost).
  • The header records more, and only what the file holds. The receptor names its biomolecule (the line was commented out), a ligand file its source file, assembly and residues, and the custom charge lines give the charge written, from any tab. The per-residue lines name only residues of the file: a chain-B receptor listed side chains completed in chain A.
  • Limits are refused up front. More chains than reduce's 62 identifiers, or more than the 99,999 atoms a PDBQT file can number, is refused with a message.

Only in ADapt

  • Symmetry copies follow their original chain. The tree lists each chain once; every choice made on a residue reaches its copies. A fragment chosen as ligand is taken from the original only, and copies that fall on an earlier copy (an ion on a symmetry axis) are written once.
  • The receptor is also written with all its hydrogens, as reduce placed them (<id>_rec_H.pdb), with reduce's choices for each histidine, asparagine and glutamine.
  • Sessions. Every edit and every file written is recorded with checksums in session.json, and a session can be reopened, also after the server restarts (Recent…).
  • A gap can be rebuilt. On request, gap by gap, ADapt builds the missing residues of a gap inside a chain (PDBFixer, then Amber ff14SB with the observed atoms fixed), checks their geometry, and writes them with the receptor, recorded in a REMARK 850 AGFR rebuilt line. Nothing is rebuilt unless asked, and then the files are ADFR's. See rebuilding a gap.
  • An edited ion charge is used. AGFRgui's charge box was never read back, so the default charge was always written.
  • A save after a tab switch writes the new tab. AGFRgui kept the previous tab's molecule until a checkbox changed.
  • An alternate location chosen in one tab is applied in a tab opened later. AGFRgui showed the choice there, and recorded it in the REMARK, but kept the default coordinates.
  • Mutations and side-chain choices made after a save take effect.
  • Clicking a label only focuses the view. In AGFRgui, clicking the label of a partly checked category put all of its residues in the receptor while the box still showed "partly".
  • A selected ion or metal is highlighted as a sphere of the highlight colour.

Not in ADapt

  • AutoFocus toggle. ADapt always centres the view on what you click.
  • Previous / next file. ADapt opens one file at a time.
  • Maps and docking box. ADapt ends with the PDBQT files. Computing affinity maps, which is AGFRgui's next step, is done with AGFR (agfr, agfrgui) from the receptor ADapt writes.

What remains surprising or missing is on Known issues.
